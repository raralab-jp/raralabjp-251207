1. システム概要
------------------------------------------------------------
本システムは Python スクリプト (`build.py`) を用いて、
CSVデータと画像アセットから静的HTML（ギャラリーサイト）を生成する。

【主な特徴】
• 画像の WebP 自動変換（JPG/PNG → WebP）
• スマホ・PC 最適化（レスポンシブ）
• 画像読み込みの最適化（Lazy Load / WebP優先）

------------------------------------------------------------

2. 開発環境・依存ライブラリ
------------------------------------------------------------
• Python 3.x
• Pillow (画像変換用)
  → インストール: pip3 install --upgrade Pillow

------------------------------------------------------------

3. 画像処理・表示仕様（重要・変更点あり）
------------------------------------------------------------

【A. WebP 自動生成】
• ビルド時 (`build.py` 実行時)、`assets/images/thumb/` 内を走査する。
• JPG / PNG ファイルがあれば、同名の `.webp` ファイルを自動生成する。
• すでに `.webp` が存在する場合は生成をスキップする。

【B. 表示優先順位と重複排除】
• HTML生成時、同一ファイル名の JPG と WebP が存在する場合、
  **WebP を優先して採用し、JPG はリストから除外する**。
• これにより、サーバー容量を圧迫せず、かつブラウザには軽量な画像を配信する。
• ユーザー側で JPG と WebP が二重に表示されることはない。

【C. Lazy Load（遅延読み込み）】
パフォーマンス向上のため、以下のルールで `loading="lazy"` を付与する。

1. ギャラリー一覧カード画像
   → ✅ 付与する (`loading="lazy" decoding="async"`)
2. 詳細ページ：メイン画像 (Hero)
   → ⛔️ 付与しない（LCP低下を防ぐため即時読み込み）
3. 詳細ページ：サムネイル一覧 (Thumbs)
   → ✅ 付与する (`loading="lazy" decoding="async"`)

------------------------------------------------------------

4. 画像の並び順（Sorting Logic）
------------------------------------------------------------
詳細ページのサムネイルおよび 4K 表示順序は以下の優先度で決定される。

1. Cover画像（最優先）
   • ファイル名に `-cover` または `_cover` が含まれる画像。
   • 必ず先頭（Hero）に配置される。

2. CSV指定順（`image_order` 列）
   • CSV の `image_order` カラムに記載された識別子（例: `DSC_1234`）。
   • ここに記載された順序が、ファイル名順より優先される。

3. ファイル名順（降順/昇順）
   • 上記以外の画像は、ファイル名のアルファベット順で並ぶ。

------------------------------------------------------------

5. ディレクトリ・ファイル構造
------------------------------------------------------------
root/
 ├ build.py                # ビルドスクリプト（WebP生成・HTML生成）
 ├ assets/
 │   ├ data/items.csv      # 商品データ（手動編集）
 │   ├ images/
 │   │   ├ thumb/          # 一覧/詳細用画像 (JPG/PNG + 自動生成WebP)
 │   │   └ 4k/             # 高解像度画像 (Lightbox用)
 ├ gallery/
 │   └ {slug}/index.html   # 自動生成される詳細ページ
 └ index.html              # 自動生成されるトップページ

------------------------------------------------------------

6. 詳細ページ (Detail) レイアウト仕様
------------------------------------------------------------
各要素は縦積みに配置され、最大幅 720px (PC) で中央揃えとなる。

1. タイトルエリア
   • <h1> {Stone} – {Carat}ct </h1>
   • <h2> “{Design Name}” </h2>

2. Hero エリア
   • メイン画像（Cover画像）。4K版へのリンク付き。
   • 動画 (Cloudflare Stream) がある場合は Hero 直下に配置。

3. Thumbs エリア
   • 画像一覧。WebP優先表示。
   • クリックで 4K 画像を Lightbox 表示（現状は4K直接リンク）。
   • Lazy Load 適用済み。

4. Plate エリア（固定3ブロック構成）
   • [A] 日本語タイトル
   • [B] 英語スペック (Stone, Carat, Design)
   • [C] クレジット (Faceted by, Origin)

5. CTA エリア
   • 「ご購入はこちら →」リンク（CSVにURLがある場合のみ）

------------------------------------------------------------

7. 運用フロー
------------------------------------------------------------
1. 画像追加
   • 撮影した JPG を `assets/images/thumb/` と `4k/` に入れる。
   • ファイル名の頭に `slug-` を付ける。

2. データ登録
   • `assets/data/items.csv` に情報を追記する。

3. ビルド実行
   • コマンド: `python3 build.py`
   • 処理内容:
     - Pillow が不足分の WebP を生成
     - HTML 生成

4. 確認
   • 生成された HTML をブラウザで開き、画像が表示されているか確認。
